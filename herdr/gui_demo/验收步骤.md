# GUI demo 验收步骤

> demo 的用途、部署和代码结构见同目录的 `README.md`;方案与全部实施、审核、交叉验证记录见 `../claude/21-gui-demo-plan.md`。

## 0. 从一台干净的 Linux 开始

以 Ubuntu 22.04 为例,下面的命令都在这台 Linux 上执行。我们自己的验收机是 OrbStack 上的 Ubuntu VM,它和这里的差别写在本节最后。

### 0.1 装基础依赖

| 依赖 | 用途 | 安装 |
| --- | --- | --- |
| git、curl、tmux、python3、PyYAML(≥5.4) | a2a 本身;curl 用来装 herdr | `sudo apt install -y git curl tmux python3 python3-yaml` |
| 编译工具 | 编译 GUI 用的 node-pty | `sudo apt install -y build-essential` |
| Node 22(带 npm) | 运行 GUI 后端;安装插件时 fnx 要调用 npm | 用 nodejs.org 的官方包,或 nvm 安装 |
| herdr | 终端与 agent 管理(安装脚本装的是最新版;我们实测的是 0.9.3) | `curl -fsSL https://herdr.dev/install.sh \| sh` |

装好后检查:`node -v`(v22.x)、`npm -v`、`herdr --version`(实测 `herdr 0.9.3`;版本不同时以实际行为为准)、`tmux -V`、`python3 -c "import yaml"` 都能运行,并且都在 PATH 里。

然后取一份源码(放在哪里都可以,下面用 `~/A2A`)。**这份源码不是给插件用的**(插件由 fnx 自己下载,见 0.3),而是给 GUI 和 a2a 后端用的:GUI 从这里构建,插件发消息时调用的 `a2a send` 也从这里运行。所以它最好和插件是同一个版本(这里是 v0.2.3):

```bash
git clone https://github.com/HwJhx/A2A.git ~/A2A
git -C ~/A2A checkout a2a-plugin-v0.2.3
```

### 0.2 装 fnx_dv 和 fnx_sw

**这是外部前提**:fnx 的安装包和安装说明由 forenyx 提供,不在本仓库里,请向提供方获取;装好后配好模型账号。GUI 默认到下面两个位置找它们:

```
~/.forenyx/fnx_dv/bin/fnx_dv
~/.forenyx/fnx_sw/bin/fnx_sw
```

装在别处的话,启动 GUI 前用 `GUI_DEMO_LAUNCHER_DV`、`GUI_DEMO_LAUNCHER_SW` 两个环境变量指定;下文的安装、查看、卸载命令也要换成实际路径。

检查:直接运行 `~/.forenyx/fnx_dv/bin/fnx_dv`,能进到 fnx 界面就行。看完按 Ctrl+C 退出(必要时按两次),**不要输入内容再回车**,否则会调用模型。

### 0.3 装 a2a 插件

**一个插件包含两样东西**:一是给模型用的 `a2a_send` 工具,二是给人用的 `/a2a` 斜杠命令。它们在同一个文件里(`herdr/a2a/pi-extension/a2a.ts`),装一次两样都有,不用分开装。插件只在 a2a 或 GUI 启动的 agent 里生效;单独打开 fnx 时它什么都不做,也不会出现 `/a2a`。

fnx_dv、fnx_sw 各有一份配置,要**分别**安装:

```bash
~/.forenyx/fnx_dv/bin/fnx_dv install git:github.com/HwJhx/A2A@a2a-plugin-v0.2.3
~/.forenyx/fnx_sw/bin/fnx_sw install git:github.com/HwJhx/A2A@a2a-plugin-v0.2.3
```

- 安装时 PATH 里必须有 npm,否则会报 `Executable not found in $PATH: "npm"`。
- 查看是否已装:`~/.forenyx/fnx_dv/bin/fnx_dv list`(fnx_sw 同理)。
- 升级:把标签换成新版本,再执行一次 install,旧版本会被替换掉;`~/A2A` 也要 `git checkout` 到同一个标签(见 0.4 最后一条)。
- 装好或升级后,**已经在运行的 agent 要先"停止"再"重启"**才会加载新插件。agent 终端的启动画面里,`[Extensions]` 下能看到 `a2a.ts`。
- 同一个 fnx 不要再用 `a2a plugin install`(软链接方式)另装一份,否则插件会加载两次。

**卸载:**

```bash
~/.forenyx/fnx_dv/bin/fnx_dv remove git:github.com/HwJhx/A2A
~/.forenyx/fnx_sw/bin/fnx_sw remove git:github.com/HwJhx/A2A
```

卸载时带不带 `@标签` 都可以,克隆下来的代码会一并删掉。卸载后同样要重启 agent 才生效;之后 agent 里就没有 `a2a_send` 和 `/a2a` 了。

### 0.4 启动 Web GUI demo

```bash
cd ~/A2A/herdr/gui_demo
npm ci && npm run build              # 第一次,或代码更新之后
export GUI_DEMO_A2A_SRC=~/A2A/herdr/a2a/src   # 必须设:默认值是我们 Mac 上的路径
export GUI_DEMO_HOST=127.0.0.1                # 建议只监听本机,见下文
bin/start                            # 后台启动,打印登录地址
```

- 两个 `export` 只在当前终端有效,每次 `bin/start` 前都要有(可以写进 `~/.bashrc`)。
- 打开 `bin/start` 打印的地址(形如 `http://127.0.0.1:8765/#token=…`)就进去了。之后在同一个浏览器里刷新,仍然是登录状态。
- **登录地址只能用一次**。换浏览器、地址已经用过、后端重启过,都要重新取:`bin/login-url`。
- 停止:`bin/stop`。herdr 会话和 agent 会保留,下次 `bin/start` 之后接着用。
- 不设 `GUI_DEMO_HOST` 时,后端监听 eth0 的地址,**同一网络里的其他机器都能访问到**。demo 没有账号体系,所以建议只监听 127.0.0.1;需要从别的机器访问时,用 SSH 端口转发:`ssh -L 8765:127.0.0.1:8765 <这台机器>`,然后在本地浏览器打开登录地址。地址要原样用 `127.0.0.1`,不要换成 `localhost`(后端会核对来源地址)。
- 端口用 `GUI_DEMO_PORT` 改(默认 8765);数据目录用 `GUI_DEMO_HOME` 改(默认 `~/.a2a_gui_demo`)。
- 检查后端是否在运行:`curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8765/`,返回 200 就是在运行。
- 后端调用的 a2a 和插件要来自**同一个版本**的代码。换插件版本时:`git -C ~/A2A fetch --tags && git -C ~/A2A checkout <同一个标签>`,重新 `npm ci && npm run build`,再 `bin/stop`、`bin/start`。

### 0.5 有哪些目录

| 目录 | 是什么 |
| --- | --- |
| `~/A2A/herdr/gui_demo` | GUI 程序(源码,以及构建出来的 `server/dist`、`web/dist`) |
| `~/.a2a_gui_demo` | GUI 的数据:`projects.json`(工程列表)、`projects/<工程id>/state/`(每个工程的消息、审计日志等)、`server.log` |
| 新建工程时填的"项目路径" | agent 的工作目录,以及这个工程的 `topology.yaml`(见 §8) |
| `~/.forenyx/fnx_dv`、`fnx_sw` | fnx 本体,以及各自的插件配置 |

删除工程时,会删掉 `~/.a2a_gui_demo` 里这个工程的数据和 `topology.yaml`,**不删** agent 的工作目录。

### 0.6 我们的验收机(OrbStack VM)和上面的差别

- Node 装在 `~/.local/lib/node-v22.20.0-linux-arm64`,**npm 不在登录 shell 的 PATH 里**。安装插件前要先执行:`export PATH=$HOME/.local/lib/node-v22.20.0-linux-arm64/bin:$PATH`。
- GUI 不从仓库直接运行。代码在 Mac 上,由 `gui_demo/bin/deploy-vm.sh` 复制到 VM 的 `~/gui_demo_run`,再在 VM 上安装依赖、构建。因为 VM 直接读 Mac 上的文件时,偶尔会读到旧内容。
- a2a 直接读 Mac 仓库(经 OrbStack 挂载),所以不用设 `GUI_DEMO_A2A_SRC`;后端监听 VM 的内部地址,Mac 浏览器用 `http://192.168.139.41:8765` 访问。这个 IP 在 VM 重启后可能变,以 `bin/start` 打印的为准。`ubuntu.orb.local` 会被代理软件解析错,打不开。
- 启动、取登录地址、停止:在 Mac 上执行 `orb -m ubuntu bash -lc '~/gui_demo_run/bin/start'`(`login-url`、`stop` 同理)。
- 我和 codex-test 测试时用的是其他目录和端口(`~/gui_demo_dev`、`~/gui_demo_xcheck`、`/tmp`),不影响验收实例。

- [ ] 点工程卡片进入。左边是"验证智能体 / 软件智能体",右边是当前这一类的 agent。
- [ ] 在"验证智能体"下点"+ 新增 IP",输入 `uart`,点"新增"。约 10 秒后出现 `dv_uart` 卡片,下面是真实的 fnx_dv 终端。

### 3.1 手动发送 `/a2a`(不调用模型)

需要按 §0.3 装好插件(v0.2.3 及以上),并重启过 agent。

- [ ] 输入 `/a2`(不要回车):补全列表里 `a2a` 一行显示 `[v0.2.3] 手动发送 a2a 消息…`,不再显示 GitHub 地址。用退格删掉。

- [ ] 在 dv_uart 的终端输入 `/a2a` 回车:列出可用的边:每条边一段,第一行 `边1: ● dv_done → sw_uart`(彩色),下一行 `消息内容: …`,长消息折行后对齐到"消息内容: "之后,边与边之间空一行。**以 `/a2a` 开头的输入由插件处理,不会调用模型。**
- [ ] 输入 `/a2a dv_done` 回车:显示 `[a2a] 已发送给 sw_uart(msg_id=…)`;dv_uart 的用量仍是 0.0%。
- [ ] 消息会投递到 sw_uart 的终端,**sw_uart 收到后会调用模型**(这是对方处理消息);不想调用模型就只做上一步之前的检查。
- [ ] 输入 `/a2a nope` 回车:红字"没有这条边",不发送。
- [ ] (请顺手确认,我只做了单元测试)输入 `/a2a `(带空格)后,看是否出现边名补全提示,以及选中后能否补全。

## 4. 停止 / 重启

- [ ] 点卡片上的"停止":状态变成"已停止",终端变灰、只读,底部提示"agent 没在运行,终端只读"。终端里会露出 pane 自己的 shell 提示符,这时输入会被拦住。
- [ ] 点"重启":约 10 秒后 agent 在原来的 pane 里重新起来,终端恢复可输入,不用刷新页面。

## 5. 删除

- [ ] 点"删除整个 IP":确认框会列出要一起删掉的 `dv_uart`、`sw_uart`。确认后两张卡片都消失。
- [ ] 回到工程列表,点工程卡片右上角的"删除":确认框会写明删除哪些东西(含项目路径下的 `topology.yaml` 和 `.bak`),以及保留 `topology.yaml.lock` 和各 agent 的工作目录。确认后卡片消失;项目路径下 `topology.yaml` 没了,agent 工作目录还在。

- [ ] 回到工程列表(刷新一下),卡片显示"herdr 会话未运行"和"恢复"按钮。
- [ ] 点"恢复",约 10–20 秒后变回"运行中"。进入页面二,agent 回来了,终端正常显示。

## 8. 动态配置测试(拓扑与消息模板)

**配置在哪里**:每个工程一份,**在工程的项目路径下**:`<项目路径>/topology.yaml`,比如 `~/projects/SoC-A/topology.yaml`。页面二标题下方的"拓扑"就是它的完整路径。旁边会有 a2a 生成的两个文件:`topology.yaml.bak`(上一个版本的备份)和 `topology.yaml.lock`(空的锁文件)。**消息模板就是每条边的 `template` 字段**,`{ip}` 在发送时替换成实际的 IP 名。新建工程时写入的是 GUI 内置的三条边:`dv_done`(dv → sw)、`sw_test_pass`、`sw_test_fail`(sw → dv)。

> 这项改动(21 号文档 §11)之前建的工程,拓扑仍在旧位置 `~/.a2a_gui_demo/projects/<工程id>/state/topology.yaml`,页面二上显示"旧工程"。下面第 1 步的命令两种位置都能处理。
>
> 新建工程时,项目路径下如果已经有 `topology.yaml` 或 `topology.yaml.bak`(比如别的工程在用),会报错,请换一个路径。删除工程会删掉 `topology.yaml` 和 `.bak`,`.lock` 保留(空文件,不影响以后在同一路径新建)。
>
> 项目路径若是 git 仓库:想把配置纳入版本管理就提交 `topology.yaml`,把 `topology.yaml.bak`、`topology.yaml.lock` 加进 `.gitignore`。

以下都在运行 GUI 的那台 Linux 上做(OrbStack VM 用 `orb -m ubuntu` 进入)。第 1–5 步只改配置、只读查看,**不发送消息、不调用模型**。

1. **设好这个工程的环境**(把 `P` 换成你的工程 id):

   ```bash
   P=pec3f31e1
   export A2A_STATE_DIR=~/.a2a_gui_demo/projects/$P/state
   # 拓扑文件:新工程在项目路径下(工程记录里有 topology 字段),旧工程在状态目录里
   export A2A_TOPOLOGY=$(python3 -c "import json,os;p=[x for x in json.load(open(os.path.expanduser('~/.a2a_gui_demo/projects.json'))) if x['id']=='$P'][0];print(p.get('topology') or os.environ['A2A_STATE_DIR']+'/topology.yaml')")
   echo "拓扑文件:$A2A_TOPOLOGY"
   export PYTHONPATH=~/A2A/herdr/a2a/src   # a2a 源码;OrbStack VM 上是 /Users/jhx/Documents/code/personal/pi_agent/A2A/herdr/a2a/src
   export PYTHONDONTWRITEBYTECODE=1
   alias a2a='python3 -m a2a.cli'
   # 以某个 agent 的身份查看它能用的边(只读):第一个参数是角色,第二个是 IP
   as_agent() { local pane; pane=$(python3 -c "import json,os;print(json.load(open(os.environ['A2A_STATE_DIR']+'/registry.json'))['agents']['$1_$2']['pane_id'])"); A2A_PROJECT_ID=$P A2A_ROLE=$1 A2A_IP=$2 HERDR_PANE_ID=$pane HERDR_SESSION=guidemo_$P python3 -m a2a.cli "${@:3}"; }
   ```

2. **看当前配置**:
   - [ ] `a2a topology show`:能看到 roles、ips、edges 和各自的 template。
   - [ ] `as_agent sw uart edges`:列出 sw_uart 能用的边,以及 `{ip}` 换成 uart 之后的文字。

3. **改模板**:

   ```bash
   a2a topology set-template dv_done '{ip} ip 验证完成,请开始驱动开发(动态配置测试,不要真的去做)'
   as_agent dv uart edges
   ```

   - [ ] 命令返回 `"ok": true` 和新的 revision;`dv_done` 的文字已变成新模板(`{ip}` 换成了 uart)。
   - [ ] `as_agent dv spi edges` 看到的是同一模板、IP 换成 spi。

4. **加一条边**:

   ```bash
   a2a topology add-edge sw_question sw dv '{ip} 的寄存器手册有疑问,请确认(动态配置测试)'
   as_agent sw uart edges
   ```

   - [ ] sw_uart 多了 `sw_question`,目标是 `dv_uart`;dv_uart 那边看不到它(方向是 sw → dv)。
   - [ ] 不能跨 IP:sw_uart 的 `sw_question` 目标永远是 `dv_uart`,不会是 `dv_spi`。

5. **删一条边**:

   ```bash
   a2a topology remove-edge sw_question
   as_agent sw uart edges
   ```

   - [ ] `sw_question` 不见了。
   - [ ] 拓扑变更都记进了审计日志:`grep TOPOLOGY_CHANGED $A2A_STATE_DIR/audit.jsonl`。

6. **(可选,会调用模型)真的发一条**:

   ```bash
   as_agent dv uart send dv_done
   ```

   这条命令本身不调用模型,但消息投递到 sw_uart 后,sw_uart 的 fnx 会把它当作提示词处理,**会调用模型**,也可能按模板再回一条消息。确认无误再执行。
   - [ ] 返回 `msg_id`、状态 `QUEUED`,文字是第 3 步改过的新模板;在页面二的 sw_uart 终端里能看到收到这条消息。
   - 已经在排队的消息不会因为后来改了模板而变化;改完之后发的才用新模板。

7. **还原**(把模板改回去,并删掉测试时加的边):

   ```bash
   a2a topology set-template dv_done '{ip} ip 我已经完成了uvm验证，你需要对这个{ip} ip进行 驱动程序开发和HAL框架开发。不要真的去做，直接用 a2a_send 回复测试成功或测试失败（二选一）'
   a2a topology show
   ```

说明:

- 也可以直接编辑 `topology.yaml`(文件头写着人工编辑后会自动重新加载),但写错格式会加载失败,建议先备份或优先用命令。
- IP 的增删请用 GUI(或 `a2a ip add/remove`)。`a2a topology add-ip/remove-ip` 只改拓扑,不会启动或停止 agent。
- 角色(roles)没有命令行入口;demo 也只认 dv、sw 两类。
- 装好插件(§0.3)后,插件每一轮都会刷新可用的边:模型下一轮就能用 `a2a_send` 发新边,`/a2a` 也会列出新边。

## 9. 验收之后

- 停止后端:`bin/stop`(见 §0.4;herdr 会话和 agent 保留,下次 `bin/start` 后继续可用)。
- 不再需要插件时,按 §0.3 卸载。

- 要彻底清掉验收时建的东西:先在页面上把工程都删掉,再停止后端。删除工程不会删项目路径下 agent 的工作目录和空的 `topology.yaml.lock`,需要的话手动删 `~/projects/<名称>`。
- 已知限制见 `../claude/21-gui-demo-plan.md` §8。主要几条:
  - 不支持单独删除一类智能体;
  - 从外部用 a2a 命令行停止 agent 时,终端约 2 秒后才变只读;
  - 没有账号登录和多用户。
